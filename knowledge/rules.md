# Srhino 告警研判规则

本文件是 Srhino 安全运营日报 Agent 的领域知识说明。机器执行参数位于
`knowledge/srhino_rules.json`，由 `tools/aggregate_alerts.py` 在生成日报前读取；
因此规则不是只写在文档里的描述，规则判定会进入 AI 研判结果和日报正文。

## 1. 证据门槛与人工复核

- 只有 `analyst_requested=true` 且 `evidence_level=full_http` 的事件才能进入原始包研判。
- 请求或回包缺失、状态码与设备动作矛盾、或只能看到单一关键词而没有上下文时，规则输出“无法判断”，并将 `human_action_required` 设为“是”。
- 模型不得把“规则命中”直接等同于“攻击成功”；必须同时引用请求特征、回包状态、设备动作和业务上下文。
- 证据不足时只创建人工复核任务，不自动封禁 IP、不修改规则或生产配置。

## 2. SQL 注入（SRH-SQLI-001）

- 强特征包括恒真条件（如 `OR 1=1`）、`UNION SELECT`、注释截断（`--`、`/*`）或时间盲注函数；先 URL 解码再匹配。
- 强特征同时出现 403/406 等阻断响应或设备动作“拦截”，判为“真实攻击尝试”。
- 只有 `select`、`or` 等业务关键词，且响应为正常 2xx JSON/页面，没有引号闭合、UNION、注释或数据库错误，判为“疑似误报”。
- 载荷存在但回包缺失、状态码异常或没有足够上下文时，不能判断是否利用成功，必须转人工。

## 3. 跨站脚本（SRH-XSS-001）

- 先对 URI 和请求体解码，识别 `<script`、事件处理器（如 `onerror=`）和 `javascript:` 等载荷。
- 回包为 2xx 且将标签转义为 `&lt;script&gt;` 等 HTML 实体，未出现未转义载荷，判为“疑似误报”，建议核查输出编码。
- 回包中出现未转义的脚本载荷并被浏览器可执行地反射，判为“真实攻击风险”。
- 只有请求载荷、没有回包或无法确认输出上下文时，输出“无法判断，需人工复核”。

## 4. 暴力破解（SRH-BRUTE-001）

- 同一源 IP、同一账号在时间窗口内出现连续口令尝试，或出现 `guess-001`、`guess-002` 等序列化口令，是强关联信号。
- 429、Retry-After、人机校验未通过说明设备已限速/挑战，但不能证明登录成功；结论应写为“真实攻击（尝试）”，并保留人工确认。
- 单条请求不能还原完整尝试序列，必须结合该源 IP 的时间窗口、账号范围和 MFA/登录日志。

## 5. 路径穿越（SRH-PATH-001）

- URI 或参数中出现至少两层 `../`、URL 编码的 `%2e%2e`，并指向 `/etc/passwd`、`win.ini` 等系统文件，判为明确的路径穿越意图。
- 设备返回 403 且动作是“拦截”时，判为真实攻击尝试但未证明读取成功。
- 只出现单层相对路径、业务下载路径正常返回，或目标文件和回包不明确时，不能仅凭字符串下结论。

## 6. 敏感数据暴露（SRH-DATA-001）

- 回包出现 `password`、`token`、`secret`、身份证号、手机号等敏感字段，且状态为 2xx，才进入高优先级核查。
- 仅凭响应长度不能证明泄露；长度异常需要和同接口正常响应基线比较。演示规则使用 500 字节作为“需要进一步核查”的提示阈值，不直接判定泄露。
- 没有回包正文、字段已脱敏或无法建立业务基线时，必须输出“无法判断，需人工复核”。

## 7. 规则失效与误判边界

- URL 编码、大小写、双重编码和 JSON 转义可能造成漏匹配，规则执行前应保留原文并进行一次解码；不能无限递归解码。
- WAF 403 只证明设备阻断，不证明应用未曾暴露或攻击者没有其他入口；高危事件仍需核查应用和主机日志。
- 扫描器 User-Agent、单一关键字、单次 200 响应都不能单独作为真实攻击依据。
- 维护窗口、压测和安全测试可能制造 XSS/SQLi/暴力破解告警，需结合责任单位和变更记录人工确认。
